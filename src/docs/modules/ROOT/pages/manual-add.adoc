= Manual Add
include::_attributes.adoc[]
:description: Adding an item without scanning a working barcode — by typing an identifier, searching online, filling in a form, or reading text off a cover photo.

Not every item has a barcode that scans cleanly.
Old VHS tapes, hand-labelled discs, rare releases the online sources can't resolve, or anything you'd rather add from memory can all be catalogued by hand instead.

image::screenshots/ios/manual-add.png[The Add Item Manually form with type-aware fields,role=screenshot,width=360]

There are two ways into manual add:

* Tap *Quick Add* on the Dashboard, next to *Quick Scan*, to open the *Add Item Manually* screen directly.
* Try to scan a barcode first — if it isn't recognised, you'll land on the same form with a *Barcode Not Found* message and a few extra shortcuts (see xref:scanning.adoc[Scanning Barcodes]).

== Typing a barcode, ISBN, or IMDb ID

If you know the number but the camera or scanner won't pick it up, you can type it in directly rather than filling in every field by hand.

* On Android and iOS, tap the keyboard icon on the scan screen to open an *Enter Barcode* dialogue with a *Barcode / ISBN / IMDb ID* field and a *Look up* button.
* On macOS, Windows, and Linux, the same field is always on screen — just type into it and press Enter.

Whatever you type is run through the same lookup as a real scan: EAN-13 and UPC-A barcodes, ISBN-10 and ISBN-13 book numbers, and IMDb IDs are all recognised.
An IMDb ID is entered as `tt` followed by digits, for example `tt0111161`, and is sent straight to TMDB rather than treated as a retail barcode.

TIP: This is often the quickest option for a damaged or oddly-printed barcode — you avoid re-typing every field only to find the number would have resolved metadata automatically.

== Filling in the form

The form itself uses the same fields either way: Title, Subtitle, Year, Format, Publisher, Description, and Media Type.

The Subtitle field relabels itself depending on the Media Type you pick, so you're not stuck typing an artist name into a field labelled "Subtitle":

[cols="1,1",options="header"]
|===
| Media Type | Subtitle field becomes

| Music | Artist
| Book | Author
| Game | Platform
| Film / TV / Unknown | Subtitle
|===

Tappable suggestion chips appear under some fields to save typing:

* *Format chips*, tailored to the Media Type — for example DVD, Blu-ray, and 4K Blu-ray for Film/TV, or Hardcover, Paperback, eBook, and Audiobook for Books.
* *Platform chips* (PS5, PS4, Xbox Series X\|S, Xbox One, Switch, PC) when the Media Type is Game.
* *Resolution chips* (such as 480p/576p for DVD, or 720p/1080p for Blu-ray) once you've picked a Film/TV format that doesn't already imply a resolution.

== Searching online for metadata

Once you've typed at least a title, tap *Search online* to look it up rather than typing every field by hand.
The search combines your Title and Subtitle fields — for example, a Title of "Gladiator" with an Artist of "Hans Zimmer" searches for "Gladiator Hans Zimmer".

Which online source is used depends on the Media Type you've selected:

[cols="1,2",options="header"]
|===
| Media Type | Searched via

| Film / TV | TMDB
| Music | MusicBrainz, then Discogs
| Book | Google Books, then Open Library
| Game | IGDB (requires a Twitch Client ID and Secret in Settings)
| Unknown | TMDB, then MusicBrainz, then Google Books, in turn
|===

What happens next depends on what comes back:

* A single confident match fills in the form fields for you, with a confirmation snackbar.
* Several possible matches open a list of candidates with cover art — tap the right one to fetch its full details.
* No matches leave the form as you left it, with a "No matches found online" message.

WARNING: Film and TV searches need a TMDB API key, and Game searches need a Twitch Client ID and Secret, both configured in xref:api-keys.adoc[API Keys].
Without the right key, the search stops before it starts and tells you which key is missing.
Music and Book searches don't require any key.

== Reading text from a cover photo

If a scan comes back as *Barcode Not Found*, one of the options offered is to read the item's cover instead of typing everything by hand:

* On Android and iOS, tap *Scan cover* to photograph the cover with the camera.
* On macOS, Windows, and Linux, tap *Pick cover image* (or *Capture cover* if a webcam session is already running) to choose or capture a photo.

Support for reading the text varies by platform:

[cols="1,2",options="header"]
|===
| Platform | Text recognition

| Android / iOS | On-device recognition
| macOS | The system Vision framework
| Windows / Linux | Not currently available
|===

NOTE: On Windows and Linux, cover text recognition isn't wired up yet — choosing to scan the cover on those platforms simply takes you to the manual form with nothing pre-filled.

When it works, any title, artist, or year the app could make out pre-fills the form, alongside a confidence banner:

* *High confidence* — results should be accurate.
* *Medium confidence* — please verify the details.
* *Low confidence* — consider entering details manually.

Whatever comes out of the cover photo is only a starting point for the same *Search online* step described above, so check the pre-filled fields before saving, especially at medium or low confidence.

== Saving

Tap *Save to Collection* when you're happy with the form.
Items added this way get an internal placeholder identifier in place of a real barcode, so features that depend on having a barcode — duplicate checking, sync, and so on — keep working normally even though the item was never scanned.
