= Rip Library
include::_attributes.adoc[]
:description: Point the app at a folder of ripped FLAC/MP3 albums, compare coverage against your physical collection, and check rip quality.

The rip library is a *desktop-only* feature — it appears in the sidebar on macOS, Windows, and Linux, and is not available on Android or iOS.
It scans a folder of ripped albums on your computer and links them to the physical items already in your collection, so you can see at a glance what you have ripped and how good those rips actually are.

image::screenshots/desktop/rips.png[Rip library showing scanned albums with coverage and quality indicators, role=screenshot, width=720]

== Pointing the app at your library

. Open *Settings → FLAC Library*.
. Set the *Library root path* to the folder that contains your ripped albums.
. Tap *Scan Now*.

CAUTION: On macOS, you *must* set the folder using the *Browse…* button next to the path field — do not type or paste the path directly.
macOS runs the app in a security sandbox, and only a folder chosen through the system's own picker grants the app permission to read it.
A typed path that looks correct will still fail, because the app was never granted access to it.
This is the single most common source of confusion on macOS — if scanning reports no albums found, or an access error, this is the first thing to check.

Once granted via Browse…, the folder stays accessible across restarts, so you only need to do this once.
On Windows and Linux, typing or pasting a path works normally.

The scanner reads the tags embedded in each FLAC or MP3 file rather than relying purely on folder names, and it understands accompanying CUE sheets for albums ripped as a single disc image.
A first scan of a large library can take a few minutes; later scans only revisit files that have changed.

== Cover artwork

The app tries to find artwork for each ripped album automatically, in this order:

. A folder image named `cover`, `folder`, `album`, or `front` (`.jpg`, `.jpeg`, or `.png`) sitting alongside the tracks.
. Artwork embedded directly in the FLAC file itself, if no folder image is found.

Once found, the artwork is cached locally so it appears instantly on later visits without being re-extracted every time.

== Coverage: what you've ripped and what you haven't

The coverage view compares your physical collection against your ripped albums and sorts every match into one of four states:

[cols="1,3", options="header"]
|===
| State | Meaning

| Fully ripped
| The album is ripped and matched to a physical item, with all tracks present.

| Partially ripped
| Some but not all of the album's tracks have been ripped.

| Not ripped
| The physical item has no corresponding rip at all.

| Quality issues
| The album is ripped, but quality analysis has flagged a problem with one or more tracks.
|===

A ripped album that the scanner could not automatically match to anything in your physical collection still appears in the library — you can match it by hand from the rip library screen.
Filter chips at the top of the coverage view let you narrow the list down to just one state, for example to see everything still outstanding.

== Checking rip quality

Quality analysis is separate from scanning, and you run it on demand — either for a single album (*Analyse Quality*) or across everything at once (*Analyse All*).
It runs in the background so the app stays responsive while it works, and results are stored so you are not re-checking the same tracks every time you open the library.

=== AccurateRip verification

AccurateRip is a community-maintained database of checksums for CD rips.
The app computes a checksum for each track and checks it against the database, reporting one of three outcomes:

[cols="1,3", options="header"]
|===
| Result | Meaning

| Verified
| The checksum matches the database. The rip is considered bit-perfect.

| Mismatch
| The checksum was found in the database, but does not match — the rip likely contains an error.

| Unknown
| The disc isn't in the AccurateRip database, or the check couldn't reach it. This is not itself a sign of a bad rip.
|===

AccurateRip verification needs an internet connection; once a track has been checked, the result is remembered so you don't need to re-check it every time.

=== Click, pop, clipping, and dropout detection

Alongside AccurateRip, the app analyses the audio itself for clicks, pops, clipping, and dropouts — the kinds of defects that come from disc damage or a rip gone wrong rather than from a data error alone.
Tracks with a detected defect are flagged in the library so you can decide whether to re-rip them.

You can tune how aggressively this runs from *Settings → Audio Quality → Click detection sensitivity*, with three levels:

* *Low* — only flags obvious defects; fewest false positives.
* *Medium* — the default, a balance between the two.
* *High* — more aggressive; catches more defects but is more likely to flag legitimate musical transients as well.

== Looking up disc metadata (GnuDB)

If an album's tags are incomplete, you can look up its title, artist, and track names from GnuDB — a community disc database — directly from the album's detail view, provided a CUE sheet is available for that album.
This is separate from the coverage and quality features above and is purely for filling in missing metadata.
GnuDB settings, including the identifier the app sends when querying it, live under *Settings → GnuDB*.
