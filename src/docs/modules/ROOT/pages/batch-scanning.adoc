= Batch Scanning
include::_attributes.adoc[]
:description: Scanning a whole stack of items in one go, then reviewing the queue, resolving conflicts, and saving everything in bulk.

Batch mode lets you scan a shelf of items back-to-back without stopping to confirm each one, then review and save them all together afterwards.
It's the quickest way to catalogue a large stack of discs, books, or games in one sitting.

== Turning on batch mode

On the Scan screen, switch on the *Batch* toggle in the toolbar.
While it's on, every successful scan is added to a queue instead of taking you straight to a confirmation screen, so you can carry on scanning the next item immediately.

A pill showing how many items you've queued so far (for example, "12 scanned") appears once you've queued at least one — tap it at any time to jump straight into the review queue.

== What happens to each scanned item

Every item you scan while batch mode is on lands in the queue with one of these statuses, depending on what the metadata lookup found:

[cols="1,3",options="header"]
|===
| Status | What it means

| Confirmed
| A single, high-confidence metadata match was found automatically — ready to save as-is.

| Review
| More than one metadata match was found (for example, several regional releases share the same barcode) — you need to pick the right one.

| Duplicate
| Either that barcode is already in your collection, or you scanned the same item twice within this batch.

| Not Found
| No metadata could be found for this barcode.
|===

== Reviewing the queue

Open the *Batch Editor* — from the queued-items pill on the Scan screen, or the sidebar on desktop — to work through what you've scanned.
Filter tabs across the top (*All Items*, *Needs Review*, *Confirmed*, *Saved*) let you focus on one group at a time.

Each item offers an action depending on its status:

* *Confirmed* items show a *Save* action, which saves that single item immediately without waiting for the rest of the batch.
* *Review* items show a *Resolve* action (see below).
* *Duplicate* items show a *Keep* action, for when you deliberately want a second copy — for example, you own two copies of the same album.
* Any item, saved or not, can be removed from the queue.

== Resolving a conflict

Tapping *Resolve* on a *Review* item opens a dialogue listing every candidate match, each with its cover art, subtitle, and year where available.
Tap the correct one to fetch its full details and move the item to *Confirmed*.

== Bulk save

Once you're happy with the queue, tap *Sync All* — the button shows how many confirmed items are about to be saved — to write every *Confirmed* item to your collection in one go.
Saved items move to the *Saved* filter tab.
If you've set up PostgreSQL sync, saved items are then queued for upload in the background; see xref:sync.adoc[Sync].

TIP: You don't have to wait until the whole batch is confirmed.
The *Save* action next to an individual confirmed item saves it on its own straight away.

== Undo and redo

Undo and redo buttons sit in the Batch Editor's toolbar on every platform.
On desktop they're also bound to keyboard shortcuts: `Ctrl+Z` / `Cmd+Z` to undo, `Ctrl+Shift+Z` / `Cmd+Shift+Z` to redo.

NOTE: Undo history only lasts for the current session and is cleared if you close the app.
Items already saved to your collection are unaffected either way — undo can't unsave something.

== Batch history

Past sessions are kept under *Batch History* (the history icon in the Batch Editor toolbar), showing when each session happened, how many items it contained, and how many were saved.
Discarded sessions appear here too, so you can double-check nothing important was lost.

== Discarding a batch

To abandon the whole batch, tap *Discard Batch* in the toolbar, then confirm the dialogue warning that all unsaved items will be lost and cannot be recovered.
Every item that hasn't been saved yet is removed from the queue; anything already saved to your collection stays there.
